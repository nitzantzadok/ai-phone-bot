# DATABASE

PostgreSQL, accessed through Drizzle. 50 tables, UUIDv7 primary keys, timestamps everywhere,
`organization_id` on every tenant-owned row.

## Why UUIDv7

Globally unique like v4, but time-ordered, which keeps B-tree locality good on the tables
that dominate write volume: `prompt_executions`, `ai_responses`, `api_cost_records`. The
embedded timestamp is also recoverable, which is useful in forensics.

## Table groups

**Tenancy** — `organizations`, `users`, `memberships`, `businesses`, `business_locations`,
`business_rules`.

**Knowledge (the moat)** — `attributes`, `sources`, `business_entities`, `business_facts`,
`fact_sources`, `business_attributes`, `competitors`, `competitor_facts`.

`attributes` and `sources` are deliberately **cross-tenant** and contain no tenant data:
`romantic` must mean the same thing for every restaurant, or the intervention-outcome
dataset is worthless.

A fact is never a bare value. It carries `(value, sourceType, confidence, discoveredAt,
lastVerifiedAt, validFrom, validUntil, status)` and links to its sources. Superseded facts
are marked, never deleted, so history stays queryable.

**Demand** — `prompt_sets`, `prompts`, `prompt_attributes`. `prompt_sets` is what makes
"scores are only comparable within one prompt set and window" enforceable rather than a
footnote.

**Observation** — `prompt_executions`, `ai_responses`, `ai_recommendations`, `citations`,
`hallucinations`. Evaluation is stored separately from the raw response so a re-evaluation
(evaluator v2) never mutates an immutable observation.

**Action** — `opportunities`, `optimization_jobs`, `optimization_actions`, `content_versions`,
`experiments`, `agent_runs`, `agent_steps`, `structured_data`, `technical_findings`.

**Commerce and ops** — `plans`, `subscriptions`, `invoices`, `usage_records`,
`api_cost_records`, `budgets`, `google_connections`, `google_locations`, `reviews`, `jobs`,
`audit_logs`, `notifications`, `feature_flag_overrides`, `deletion_requests`.

## Conventions

- Money is **integer minor units** with an explicit currency column. No floats, ever.
- Invoices store `vat_rate_bps` **and** `vat_period_id`, so an old invoice reproduces
  exactly after the statutory rate changes.
- JSONB is used where the shape is genuinely open (crawled structured data, agent step
  payloads). Anything that needs to be queried or joined is a real column.
- `on delete cascade` from `organizations` throughout, so tenant deletion is one statement
  rather than a hand-maintained ordering.

## Migrations

Generated by drizzle-kit into `packages/database/migrations`, applied by an explicit,
observable deployment step:

```bash
pnpm db:generate   # after changing the schema
pnpm db:migrate    # in deploy
```

One transaction per file: a partial migration is never left behind.

## Testing

`packages/database/src/testing/pglite.ts` runs real Postgres compiled to WASM, in process.
Tests exercise genuine enum types, jsonb behaviour, unique constraints and `on conflict` —
with no Docker, no shared fixture database and no port contention. The schema is migrated
once per process and the data directory snapshot is cloned per test database, turning setup
into a memcpy.

## Indexing

Indexes are added deliberately, not reflexively. The ones that matter:

- `(business_id, executed_at)` on `prompt_executions` — every dashboard query is a window
- `(business_id, status, score)` on `opportunities` — the top-opportunities read
- `(business_id, prompt_set_id, calculated_at)` on `airs_scores` — score history
- `(organization_id, created_at)` on `api_cost_records` — margin reporting
- unique `(business_id, dedupe_key)` on `opportunities` — makes re-diagnosis idempotent
