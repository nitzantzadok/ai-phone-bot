# מערכת בניית תכניות אימון לסטודיו

מערכת **עצמאית לחלוטין** לבניית תכניות אימון שבועיות אישיות לכל מתאמני הסטודיו.
היא יושבת בתיקייה נפרדת, עם `package.json` משלה, ללא תלויות חיצוניות וללא כל קשר
לקוד, למסד הנתונים או לשירותים של מערכות אחרות במאגר. אפשר להעתיק את התיקייה
`studio-training/` כמו שהיא לכל מקום והיא תעבוד.

```bash
cd studio-training
npm run seed     # נתוני דמו: 7 סטודיואים שונים לגמרי, 13 מתאמנים
npm test         # 34 קבצי בדיקה, כולל מטריצת כיסוי של אלפי תכניות
npm run demo     # הדפסת תכניות לכל מתאמני הדמו
npm run build    # בניית מסך המאמן לקובץ HTML עצמאי אחד
npm start        # מסך המאמן: http://localhost:4310
```

מסך המאמן הוא קובץ יחיד שרץ במלואו בדפדפן — המנוע כולו נטען לצד ה-UI,
בלי שרת ובלי שליחת נתונים החוצה.

## מה המערכת לוקחת בחשבון

**המתאמן — מי הוא:** גיל (עם התאמות ייעודיות לנוער ולגיל השלישי), מין, גובה
ומשקל, רמת ניסיון, ותק אימונים, ואיכות התאוששות (שינה, סטרס, תזונה).

**המתאמן — מה הוא רוצה:** 13 מטרות — מסה, כוח, ירידה בשומן, כושר כללי, סיבולת,
כוח מתפרץ, שיקום, יציבה, ניידות, צפיפות עצם, תפקוד ועצמאות בגיל השלישי, ביצועים
בענף ספורט, והפגה ובריאות נפשית. לכל מטרה פרופיל מלא של סטים, חזרות, מנוחות, קצב,
RIR ועצימות.

**המתאמן — מה מגביל אותו:** 66 מגבלות רפואיות ופציעות — כתף, גב (כולל ההבחנה בין
פריצת דיסק לבין היצרות תעלה, שדורשות הפוך זו מזו), ברך, מרפק, שורש כף יד, ירך,
קרסול, צוואר, מפרקים מלאכותיים, רצפת אגן, הריון ואחרי לידה, לב וכלי דם, סוכרת,
אסתמה, אונקולוגיה, נוירולוגיה, היפרמוביליות, תשישות לאחר מאמץ ועוד. לכל מגבלה
שלוש דרגות חומרה שמשנות את קשיחות הסינון.

**המתאמן — מה קורה לו מחוץ לסטודיו:** ענף הספורט שהוא מתאמן בו וכמה פעמים בשבוע
(רץ שלוש פעמים בשבוע לא צריך עוד שלושה ימי רגליים), אורח החיים התעסוקתי, שבוע
נסיעה, אורכי אימון שונים בימים שונים, ושלב במחזור החודשי כקלט אופציונלי.

**הסטודיו:** מלאי הציוד המדויק *וכמות* כל פריט, מספר המתאמנים במקביל ומספר
המאמנים על הרצפה (מאמן שמשגיח על עשרה אנשים לא ילמד תרגיל טכני — והמערכת לא
תציע כזה), גובה תקרה, שטח פנוי, מגבלת רעש בבניין מגורים, המשקולת הכבדה ביותר
וקפיצת המשקל הקטנה ביותר, וסגנון הסטודיו — חדר כושר, פונקציונלי, בוטיק,
פילאטיס/ריפורמר, אגרוף, מרכז לגיל השלישי או סטודיו ביתי.

**התכנון עצמו:** חלוקה שבועית (גוף מלא / A-B / A-B-C / A-B-C-D / עליון-תחתון /
דחיפה-משיכה / PPL / לפי קבוצות שריר / מעגל תחנות / ניידות), פריסה על ימי השבוע
עם מרווחי התאוששות, סדר ביצוע נכון, סטי הכנה מתגברים לפני התרגיל הכבד, איזון
דפוסי תנועה, נפח שבועי לכל שריר, תדירות גירוי, תקציב עייפות יומי, תקציב זמן,
ופריודיזציה — צבירה, העצמה ושבוע הורדת עומס.

## התהליך: מהרשמה ועד תכנית

**שלב 1 — רישום הסטודיו.** בעל הסטודיו בוחר חבילת ציוד מוכנה (חדר כושר / פונקציונלי /
בוטיק / פילאטיס / אגרוף / גיל שלישי / ביתי) ומתקן ממנה, או מסמן פריטים מרשימה עם חיפוש.
אפשר גם לצלם את החדר: כשמוגדר מפתח API, המערכת מזהה את הציוד מהתמונה ומסמנת אותו לאישור —
הצילום מציע, הסימון קובע. בנוסף נשמרים משקלי העבודה בפועל (הקלה ביותר, הכבדה ביותר, קפיצת
המשקל), המרחב הפיזי (תקרה, שטח, רעש), ויחס מאמנים-מתאמנים. מונה חי מראה כמה תרגילים נפתחו.

**שלב 2 — רישום המתאמן.** ארבעה שדות מספיקים כדי להתחיל; כל השאר אופציונלי ומסודר לפי
נושאים. הפציעות נמצאות במרכז המסך, מקובצות לפי אזור גוף, עם דרגת חומרה, צד והערה חופשית.

**שלב 3 — האימון.** התכנית נוצרת מיד. תחת כל תרגיל מופיע תיאור מדויק, כך שגם מאמן שלא מכיר
את התרגיל יעביר אותו נכון.

## ייבוא מ-Google Sheets

סטודיו שכבר עובד לא מתחיל מדף ריק. יש לו גיליון: לשונית מתאמנים, לשונית ציוד, לשונית לכל
מתאמן עם התכנית שלו, ולוח נוכחות. במקום להקליד את זה מחדש, המערכת קוראת את הגיליון ובונה
ממנו את הסטודיו.

**שלוש דרכים להביא את הנתונים**, לפי הסדר שבו כדאי לנסות אותן:

1. **קובץ** — בגיליון: קובץ ← הורדה ← **Microsoft Excel (.xlsx)**. זו האפשרות הראשונה בתפריט
   וזו שמורידה את *כל* הלשוניות בקובץ אחד. הקובץ נקרא בדפדפן: xlsx הוא ארכיון ZIP של קובצי
   XML, והדפדפן יודע לפרוס אותו בעצמו — בלי ספרייה חיצונית ובלי שהקובץ עוזב את המחשב.
   אפשר גם לגרור את הקובץ למסך. נקראים גם **ods** (LibreOffice, וגם אפשרות הורדה של Google),
   **CSV/TSV** — כולל CSV שנשמר מ-Excel בעברית (קידוד windows-1255) שאחרת היה נקרא כג׳יבריש —
   ו-**JSON** של מערכת קודמת. הזיהוי הוא לפי תוכן הקובץ ולא לפי הסיומת, כך שקובץ ods בשם
   xlsx עדיין נקרא. קובץ xls ישן או PDF מקבלים הסבר מה לעשות במקום שורות ג׳יבריש.
2. **הדבקה** — סימון הכול בגיליון, Ctrl+C, הדבקה. עובד תמיד, בלי הרשאות ובלי הגדרות.
   כשהלוח מכיל HTML (וזה המצב בהעתקה מהדפדפן) נקראים ממנו גבולות התאים, כך שתא עם שתי
   שורות או תא ממוזג אינם מסיטים את שאר הטבלה. גם טבלה שהודבקה מ-PDF או מהודעה, שהעמודות
   בה מיושרות ברווחים בלבד, מפוצלת נכון.
3. **קישור ישיר** — שיתוף ← "כל מי שיש לו הקישור" ← צופה, והדבקת הכתובת. הדפדפן פונה
   ישירות ל-Google דרך נקודת הקצה הציבורית `gviz`; הנתונים עוברים מהגיליון למסך המאמן
   ולא דרך שרת שלנו, ואין צורך במפתח API או בחיבור לחשבון Google. בגיליון שלא פורסם
   לאינטרנט הדפדפן אינו מורשה לקרוא את רשימת הלשוניות, ולכן נטענת הלשונית שבקישור בלבד —
   המסך אומר את זה, ואפשר להוסיף עוד לשוניות בהדבקת הכתובת שלהן.

**מה המערכת מזהה לבד**

לכל לשונית נקבע תפקיד — מתאמנים, ציוד, תכניות, יומן ביצועים, מדידות, נוכחות או פרטי
הסטודיו — לפי שם הלשונית, לפי השדות שזוהו בה ולפי צורת הנתונים. לוח נוכחות ורשימת מתאמנים
נראים כמעט אותו דבר; מה שמפריד ביניהם הוא שהתאריכים יושבים בכותרות, ושבלוח נוכחות אותו שם
חוזר שוב ושוב בעוד רשימת מתאמנים מונה כל אדם פעם אחת.

כל עמודה נשפטת פעמיים: לפי הכותרת שלה ולפי מה שכתוב בתאים מתחתיה. ההצלבה היא מה שמאפשר
להבין ש"משקל" בגיליון מתאמנים הוא משקל גוף, ואותה מילה בדיוק בגיליון תכנית היא העומס
בתרגיל. גיליון בלי שורת כותרת בכלל עובד גם הוא — הזיהוי נעשה לפי התוכן, והשורה הראשונה
נשארת נתון ולא הופכת לכותרת בטעות.

הערכים עצמם מתורגמים לשפה של המנוע: "מתקדמת" היא רמה, "ירידה במשקל" היא מטרה, "כאבי ברך
שמאל (חריף)" היא מגבלה עם צד וחומרה, "משקולות יד 2-30" היא פריט ציוד עם טווח משקלים,
ו"סקוואט" הוא תרגיל מהמאגר. ההתאמה עמידה לשגיאות כתיב, לגרשיים, לניקוד ולאותיות סופיות.

**מה נבנה מזה**

| מהגיליון | למערכת |
|---|---|
| לשונית מתאמנים | כרטיס מתאמן מלא: גיל, מין, גובה, משקל, רמה, מטרות, מגבלות, תדירות, פרטי קשר |
| עמודת סניף | סטודיו נפרד לכל סניף, עם אותו מאגר מתאמנים |
| לשונית ציוד | מלאי הסטודיו, כולל כמויות וטווחי משקלים |
| לשונית תכנית | התכנית נשמרת בארכיון כפי שהייתה, ואפשר לפתוח אותה מהיסטוריית המתאמן |
| יומן ביצועים | רישומי סטים + משקלי העבודה האחרונים, כך שההצעות מדויקות כבר בתכנית הראשונה |
| מדידות | היסטוריית משקל, אחוזי שומן והיקפים |
| לוח נוכחות | אימונים שבוצעו בלוח השנה, ותדירות אמיתית שנגזרת מהם |

**פריסות שנתקלים בהן בשטח**, וכולן נקראות: שם מפוצל ל"שם פרטי" ו"שם משפחה"; כרטיס אישי
אנכי שבו כל שורה היא פרט אחד ("שם / גיל / משקל"); שתי טבלאות באותה לשונית מופרדות בשורות
ריקות; טלפון שאיבד את האפס המוביל כשהעמודה הוגדרה כמספר; עמודת מספר רץ שלא תיקרא כמשקל
גוף; צ׳קליסט ציוד שבו X מסמן "אין" — ורק כשיש בעמודה גם סימון חיובי להשוות אליו; שתי
מטרות בתא אחד מחוברות בו׳ החיבור; ותאריכים כמספר סידורי של Excel. תווי כיווניות ורווחים
קשיחים, שאינם נראים לעין ודבקים בשמות, מנוקים לפני ההשוואה.

**גיליון גדול.** סטודיו שמנהל לשונית לכל מתאמן מגיע עם מאה לשוניות ואלף שורות בכל אחת.
הניתוח רץ בהפוגות ומראה התקדמות, כך שהמסך ממשיך להגיב במקום להיתקע; ההשוואות מוחזקות
בזיכרון מטמון, ומה שלקח דקות לוקח שניות. יום אימון בודד מוגבל ל-40 תרגילים — לשונית עם
מאות שורות תרגילים היא כמעט תמיד יומן ביצועים בלי עמודת תאריך, והמסך אומר את זה ומסביר
איך לפצל אותה. כשהאחסון של הדפדפן מתמלא, הייבוא אומר זאת מפורשות ואינו מציג "נשמר".

**מה נחשב שם של אדם.** עמודה של תרגילים או רשימת ציוד שנקראת בטעות כרשימת מתאמנים היא
הטעות היקרה ביותר בייבוא — המערכת נפתחת עם "לחיצת חזה" ו"מוט אולימפי" כמתאמנים. לכן כל
ערך נבדק לפני שהוא הופך לאדם: מילה מתוך שם של תרגיל או של ציוד, ערך שזהה למונח במאגר,
כותרת, מספר, כתובת אימייל או משפט שלם — נפסלים. הכלל הפוך מכלל הזיהוי הרגיל: מחפשים ראיה
*נגד*, ובהיעדרה השם מתקבל, כי שם של אדם יכול להיות כל דבר. כל שורה שנפסלה מוצגת במסך
האישור עם הסיבה, כדי שגם הכיוון ההפוך — אדם אמיתי שנפסל — יתגלה מיד.

**מה שלא זוהה לא נזרק.** תרגיל שאין לו מקבילה במאגר נשמר כתרגיל של הסטודיו ואפשר להשתמש
בו; עמודה שלא זוהתה נשמרת כהערה על המתאמן; פריט ציוד ומגבלה שלא זוהו מוצגים ברשימה נפרדת
כדי שהמאמן יוסיף אותם ידנית. שורות "סה״כ" ומתאמן שמופיע פעמיים מזוהים ומטופלים.

**כלום לא נשמר לפני אישור.** מסך הייבוא מציג מה זוהה בכל לשונית ובכל עמודה, עם דוגמאות
מהתאים ועם הסיבה לכל החלטה. אפשר לשנות כל סיווג וכל עמודה, והמספרים מתעדכנים מיד. רק
לחיצה על "ייבא הכול" כותבת נתונים — והייבוא מוסיף בלבד, ולא מוחק דבר ממה שכבר רשום.

## העתקה לגיליון

הכיוון ההפוך לייבוא. מאמן שרוצה לשלוח תכנית במייל, לצרף אותה לקובץ המעקב של הסטודיו או
לשמור עותק בגיליון — לוחץ "העתק את התכנית", ומדביק בגיליון. Google Sheets מפרק טקסט מופרד
בטאבים לתאים, ולכן כל עמודה נוחתת בתא שלה בלי עיבוד נוסף.

| כפתור | מה הוא עושה |
|---|---|
| העתק את התכנית | התכנית שמוצגת כרגע, כולל תכנית מהארכיון |
| העתק את כל הסטודיו | תכנית לכל מתאמן בסניף הנבחר, בטבלה אחת |
| הורדה כקובץ | אותה טבלה כ-CSV |

העמודות הן `מתאמן · יום · סדר · תרגיל · סטים · חזרות · משקל · מנוחה · קצב · הערות` — אותה
טבלה בדיוק שמסך הייבוא יודע לקרוא. אפשר להדביק בגיליון, לערוך שם, ולייבא בחזרה בלי אובדן;
יש בדיקה שמוודאת שהסיבוב המלא שומר על אותם תרגילים, סטים וחזרות.

שני פרטים שנראים טכניים ומשנים בפועל: תא שמכיל טאב או ירידת שורה היה מפרק את השורה לתאים
שגויים, ולכן כל תא מנוקה מהם לפני ההעתקה; ושם הקובץ להורדה הוא באנגלית, כי דפדפן משמיט שם
קובץ שאין בו ASCII ומוריד אותו בשם "download" בלי סיומת — שם המתאמן ממילא נמצא בעמודה
הראשונה של הטבלה.

כשלוח המערכת חסום (עמוד שנפתח כקובץ מקומי, או דפדפן שמגביל) הטבלה נפתחת מסומנת בתיבה
ואפשר להעתיק ידנית. כפתור שלא עושה כלום הוא התוצאה הגרועה ביותר כאן.

## עריכה ומחיקה של מתאמן

ברשימת המתאמנים יש לכל שורה שלושה כפתורים: **פתח תכנית**, **ערוך** ו**מחק**.

**עריכה** טוענת את כל הפרטים של המתאמן חזרה לטופס — כולל הפציעות עם דרגת החומרה והצד,
הימים המועדפים, שרירי המיקוד, התרגילים שהוא אוהב ושלא, והתרגילים הטכניים שהוא כבר יודע —
ושמירה מעדכנת את אותה רשומה במקום ליצור מתאמן כפול. הערכים שמוצגים הם אלה שהמנוע עובד
לפיהם: אם נרשמה מדידת משקל חדשה, זה המשקל שיופיע ולא זה שהוקלד פעם בטופס.

מה שאין בטופס — יומן האימונים, המדידות, הערות המאמן, התרגילים שאושרו או נחסמו בשטח —
נשמר כפי שהוא. זה נאכף בשני מקומות: הלקוח ממזג את השינוי לתוך הרשומה הקיימת, והשרת שומר
את שדות ההיסטוריה גם אם הבקשה לא כללה אותם. עריכת שם לא אמורה למחוק חצי שנה של מעקב,
ולכן זה לא תלוי בכך שהלקוח יזכור לשלוח אותם.

**מחיקה** היא בשני שלבים: הלחיצה הראשונה מחליפה את השורה בשאלה, והשנייה מוחקת. יחד עם
המתאמן נמחקים גם ארכיון התכניות וההיסטוריה שלו — ארכיון של אדם שאינו רשום הוא מידע אישי
בלי בעלים ובלי מסך שמציג אותו. המחיקה נוגעת רק במתאמן שנבחר; הארכיון של האחרים אינו נפגע,
ויש בדיקה שמוודאת בדיוק את זה.

**מחיקה שאפשר לבטל.** אחרי כל מחיקה — של אחד או של קבוצה — מופיעה שורת "ביטול המחיקה"
שמחזירה את המתאמנים יחד עם הארכיון וההיסטוריה שלהם. העותק יושב בזיכרון של הדף עד לרענון:
הוא נועד לתקן את הלחיצה הלא נכונה של הרגע, לא לשמש גיבוי.

## מה המערכת לומדת מהאימונים שכבר היו

הצהרה של מאמן היא זיכרון; הגיליון הוא מה שקרה. אדם כותב "מתחיל" ובגיליון שלו רשומים סקוואט
מוט 4×5 עם 110 ק"ג ומתח — שתי האמירות לא יכולות להיות נכונות, והשנייה היא זו שאפשר לבדוק.
לכן הייבוא לא רק מעביר שמות: הוא קורא את התכניות הקודמות ומוציא מהן פרופיל.

| מה נלמד | מאיפה | למה זה משנה |
|---|---|---|
| רמת המתאמן | מורכבות התרגילים, כוח יחסי, ומשקלים מוחלטים | קובעת אילו תרגילים בכלל ייבחרו ומה טווח החזרות |
| ותק אימונים | הרמה שהוכחה — אי אפשר להיות באמצע הדרך אחרי אפס חודשים | תקרת הוותק לא סותרת את מה שנראה בגיליון |
| תרגילים טכניים שכבר מבוצעים | שמות התרגילים בתכניות | דדליפט ומתח נפתחים למי שכבר עושה אותם במקום להיחסם לפי רמה |
| משקלי עבודה | עמודת המשקל | התכנית הראשונה כבר מציעה משקל אמיתי: "לפי הביצוע האחרון: 110 ק״ג × 5" |
| ציוד הסטודיו | התרגילים עצמם | סטודיו בלי לשונית ציוד מגלה את עצמו דרך התכניות |

**שלוש ראיות בלתי תלויות, והכרעה אחת.** כוח יחסי (משקל חלקי משקל גוף) הוא המדויק ביותר;
מורכבות התרגילים היא ראיה בפני עצמה — אף מאמן לא רושם דדליפט למי שלא מסוגל לבצע אותו;
ומשקלים מוחלטים משמשים כשמשקל הגוף חסר. הראיה הגבוהה קובעת, כי ראיות אינן סותרות זו את זו
אלא חלקיות: מי שמבצע מתח וסקוואט מוט אך מרים משקל בינוני הוא מתאמן שעדיין לא העמיס, לא
מתחיל. הורדת רמה נעשית רק כשהראיה רחבה — שלושה דפוסים ומעלה — ותרגיל טכני בודד אינו
רפרטואר, ולכן נדרשים שניים כדי להעלות לרמת ביניים.

**כל מסקנה מגיעה עם הנימוק שלה.** מסך האישור מציג לכל מתאמן את הרמה שנקבעה ולמה, לפני
ששומרים משהו: "מבצע סקוואט מוט על הגב, מתח — תרגילים ברמת מיומנות 4", "כוח יחסי: 1.34×
משקל גוף". אפשר לשנות כל רמה ידנית בכרטיס המתאמן, ולחיצה על **למד רמה מההיסטוריה** מריצה
את אותו לימוד על מתאמנים קיימים אחרי שנצברו אצלם רישומים חדשים.

**מה שחסר נאמר במפורש.** ליד כל מתאמן מופיע מה חסר לו כדי שהתכנית תהיה מדויקת — משקל גוף,
גיל, מטרה או ראיה לרמה — ויש סינון "חסרים נתונים". משקל גוף הוא הנתון היחיד שמשפיע גם על
הצעות המשקל וגם על זיהוי הרמה, ולכן הוא מסומן בנפרד.

## סטטוס, סגנון אימון ופעולות על כמה מתאמנים

**סטטוס.** לכל מתאמן יש סימון פעיל / לא פעיל, ולחיצה על השבב מחליפה אותו. מתאמן שהפסיק
אינו נמחק — ההיסטוריה שלו נשמרת והוא עשוי לחזור — אבל הוא אינו נכלל בבניית תכניות לכולם
ואפשר לסנן אותו החוצה מהרשימה. הסטטוס מיובא גם מהגיליון, מעמודה כמו "סטטוס" או "פעיל".

**רשימה שאפשר לעבוד איתה.** מעל הרשימה יש חיפוש (שם, סניף, טלפון או מאמן) וארבעה סינונים:
הכול, פעילים, לא פעילים, ו**ללא תכנית השבוע** — הסינון שממנו מתחיל יום ראשון בבוקר. לכל
שורה מוצג מתי נבנתה לה תכנית לאחרונה.

**פעולות קבוצתיות.** תיבת סימון בכל שורה, סימון של הכול בלחיצה, ואז מחיקה של כולם יחד או
סימון קבוצתי כפעילים / לא פעילים — במקום שלוש לחיצות לכל מתאמן.

**סגנון אימון.** המטרה עונה על "בשביל מה" (מסה, ירידה בשומן); הסגנון עונה על "איך". אפשר
לבחור כמה סגנונות והם משתלבים: כוח, פיתוח גוף, אתלטיות וספורט, פונקציונלי, קונדישן,
סיבולת, ניידות ושיקום. זו אינה תווית: הסגנון מזיז את טווח החזרות, את המנוחה ואת מספר
הסטים בתוך הגבולות של התרגיל, ומשנה את בחירת התרגילים עצמם — פיתוח גוף מושך לבידוד
ולמכונות, כוח ואתלטיות למשקל חופשי ולתרגילים מורכבים. שילוב של שניים יושב באמת ביניהם.
גם הסגנון מיובא מהגיליון, מעמודה כמו "סוג אימון".

**חלוקת האימון.** ברירת המחדל לכל מתאמן חדש היא **גוף מלא**. אפשר לבחור לו כל חלוקה אחרת,
או "שהמערכת תחליט" — ואז ההכרעה חוזרת למנוע, שבוחר לפי המטרה, הרמה ומספר הימים. הבחירה
של המתאמן גוברת על ברירת המחדל של הסטודיו.

**שבוע הבא לכולם.** כפתור אחד שמקדם שבוע ובונה תכנית לכל מתאמן פעיל בסניף: מחיל את המשוב
מהשטח, מקדם את הפריודיזציה, בונה, ומארכב. מי שלא פעיל מדולג, וכל כישלון מופיע ביומן עם
השם והסיבה במקום להיעלם.

## איך זה עובד

```
מתאמן + סטודיו
      │
      ├─ normalize + validate ................ models.js
      │
      ├─ סינון: ציוד → פציעות → רמה → העדפות .. filters.js
      │        (כל פסילה מתועדת עם סיבה)
      │
      ├─ בחירת חלוקה ובניית שלד היום ......... split.js
      │
      ├─ מילוי משבצות בניקוד רב-משתני ........ select.js
      │        דפוס · חוב נפח · עודף נפח · מטרה · ציוד
      │        נדירות · גיוון · העדפות · עייפות
      │
      ├─ מרשם: סטים/חזרות/מנוחה/קצב/RIR ...... prescription.js
      │
      ├─ התאמה לתקציב זמן + השלמת נפח חסר .... generate.js
      │
      └─ בקרת איכות ......................... validate.js
               │
          תכנית שבועית + ציון איכות + ממצאים
```

**דחיסה לזמן אמת:** אם האימון לא נכנס בזמן שהוקצה, המערכת מוותרת בסדר שמאמן
מוותר בו — קודם סטים מהתרגיל הארוך, אחר כך קיצור מנוחות (עם הערה), ורק בסוף
ויתור על תרגיל שולי. אימון לעולם לא "גולש" מעבר לזמן שהמתאמן הקצה.

**עקרון מנחה:** אין "פלט קסום". כל תרגיל שנבחר נושא איתו את הניקוד שהביא לבחירתו
(`selection.detail`), את החלופות המדורגות, ואת ההערות המקצועיות — כך שהמאמן רואה
*למה* התכנית נראית כך, ויכול לחלוק עליה.

### בקרת האיכות
לפני שהתכנית מגיעה למאמן היא נבדקת: תרגיל כפול באותו אימון, תרגיל שסותר מגבלה,
ציוד חסר, טווח חזרות לא הגיוני, יחס דחיפה/משיכה, איזון סקוואט/הינג׳, שריר ללא
כיסוי, נפח מעל או מתחת ליעד, תדירות נמוכה, ואורך אימון חורג. `error` פוסל תכנית,
`warning` ו-`info` מוצגים למאמן להחלטה.

## מלאי המשקלים — מה באמת יש בחדר

"45 ק״ג" זו הצעה תיאורטית. השאלה המעשית היא אם אפשר להרכיב 45 ק״ג מהציוד שעומד בחדר.

ברישום הסטודיו מגדירים בדיוק אילו משקולות יד, קטלבלים, פלטות ומוטות יש — **ובאיזו כמות מכל
משקל**. אפשר למלא סט סטנדרטי בלחיצה ואז לתקן. מכאן המערכת:

- מציגה **פירוט הרכבה**: "מוט 20 + 2×10 + 1×5 לכל צד" במקום מספר שאי אפשר לבנות.
- לא מציעה זוג משקולות כשיש ממנו רק אחת.
- בוחרת מוט לפי התרגיל — סקוואט לא נבנה על מוט EZ, וכפיפת מרפקים כן.
- מתאימה למחסניות מכונה לפי הקפיצה שלהן.

## מדידות והתקדמות

לכל מתאמן יומן מדידות לפי תאריך: משקל, אחוז שומן, והיקפי חזה, מותן, ירכיים, ירך, זרוע, שוק
וצוואר. אפשר למדוד רק חלק — שדות ריקים לא נשמרים.

ההיסטוריה מוצגת כ**גרף נפרד לכל מדד**, כי ק״ג, אחוזים וסנטימטרים אינם חולקים ציר. כל גרף מציג
את הערך הנוכחי, את השינוי מאז המדידה הראשונה, וחץ שמראה אם השינוי בכיוון הרצוי — ירידה במותן
היא הצלחה, ירידה בהיקף זרוע אינה.

**המדידה האחרונה היא זו שמזינה את חישוב המשקלים**, כך שכשמתאמן יורד 5 ק״ג התכנית מתעדכנת
מעצמה בלי שאף אחד צריך לזכור.

## משקלי עבודה בקילוגרמים

לכל תרגיל שמעמיסים בו מופיע משקל עבודה בק״ג, לא טווח מעורפל. סדר העדיפויות:

1. **מה שהמאמן קבע** — שינוי המשקל בתכנית הופך אותו למשקל העבודה של המתאמן, נשמר, ומוצג
   בשבוע הבא. הפרוגרסיה ממשיכה ממנו.
2. **מה שנרשם בפועל** — סט שנרשם מייצר הערכת 1RM והמשקל נגזר מאחוז העצימות של המטרה.
3. **הצעת פתיחה** — כשאין היסטוריה, המערכת מציעה משקל שמרני לפי משקל הגוף, הרמה, הגיל
   ומשפחת התרגיל, מעוגל לקפיצת המשקל שבאמת קיימת בסטודיו ומוגבל למשקולת הכבדה ביותר שיש.
   ההצעה מסומנת במפורש כ"לאמת בסט חימום".

המערכת גם יודעת כשתרגיל כבר הגיע לתקרת הציוד: אם המשקל הדרוש למתאמן עובר את המשקולת הכבדה
ביותר בסטודיו, התרגיל לא ישמש כתרגיל עיקרי — הוא כבר לא מאפשר התקדמות.

## אין תרגילים קלים למתאמן מתקדם

לכל תרגיל יש דירוג **דרישה** (1-5) שנגזר מהעייפות שהוא מייצר, מהיכולת להעמיס עליו ומהאם
הוא גרסה מוקלת. לתרגיל עיקרי יש רצפה לפי רמת המתאמן — בינוני 2, מתקדם 3 — כך שמתאמן מתקדם
לא יקבל שכיבות סמיכה לקיר או חתירה בגומייה כתרגיל מרכזי רק משום שהם בטוחים. הרצפה היא קנס
ניקוד חזק ולא פסילה, כדי שבסטודיו שבו אין ברירה התכנית עדיין תיבנה.

## יומן המאמן — הערות שמשנות את התכנית

הרבה ממה שקובע תכנית טובה קורה באימון ולא בטופס. לכן לכל מתאמן יש יומן הערות, וכל הערה
יכולה לשאת **הנחיה** שהמנוע מבצע בפועל:

| הנחיה | מה קורה |
|---|---|
| להימנע מתרגיל / להעדיף תרגיל | התרגיל יוצא מהתכנית או מקבל עדיפות |
| להימנע מדפוס תנועה | הדפוס לא ישובץ כלל |
| להדגיש שריר | השריר הופך לשריר מיקוד |
| להיזהר במפרק | תרגילים עם עומס גבוה על אותו מפרק מקבלים עדיפות נמוכה |
| להוריד / להעלות משקלי עבודה | כל המשקלים בתכנית מתוקנים באחוז שנקבע |
| להוריד / להעלות נפח | מכפיל הנפח השבועי משתנה |
| לקצר את האימון | אורך האימון מוגבל |
| ציוד לא זמין | הציוד יוצא מהחישוב |
| הערה בלבד | נשמרת ומוצגת, בלי לשנות דבר |

כל הערה ניתנת לעריכה, להשבתה (הטקסט נשמר וההשפעה נעצרת) או למחיקה. התכנית מציגה לצד כל
הערה פעילה מה בדיוק היא עשתה.

## פציעה אינה גזר דין

מגבלה רפואית היא כלל זהירות, לא נבואה. לפעמים הפציעה ישנה, קלה, או פשוט לא רלוונטית לתנועה
מסוימת — והדרך היחידה לדעת היא לנסות בזהירות ולשאול.

לכל אזור פגוע המערכת מציעה **תרגיל בדיקה אחד**: הכי פשוט והכי בטוח שקיים לאזור, בסט אחד,
בעומס מינימלי, עם הוראות ביצוע וכלל עצירה מפורש. אם הוא עבר בלי כאב — התרגיל נרשם כמאושר
עבור המתאמן הזה וייכנס לתכניות הבאות **למרות המגבלה**. אם היה כאב — הוא נחסם לצמיתות עם
הסיבה, והמגבלה נשארת במלוא תוקפה.

ההתקדמות היא כמו של פיזיותרפיסט: איזומטרי → קימה מכיסא → סקוואט לספסל → ואם אין יותר תרגיל
עדין מספיק, המערכת פשוט לא מציעה.

שלושה קווים שאינם ניתנים לפתיחה:

1. **מצבים מערכתיים אינם שאלה של תחושה.** הריון, מצב לבבי, אוסטאופורוזיס או אפילפסיה אינם
   "אולי היום זה בסדר" — עבורם לא מוצע תרגיל בדיקה כלל.
2. **תרגיל בדיקה לעולם אינו נושא זעזוע, תנועה בליסטית או עצירת נשימה** — אלה שוללים את
   היכולת לעצור באמצע, וגם אינם בודקים שום דבר מועיל.
3. **בשלב חריף הבדיקה נעולה** ונפתחת רק בלחיצה מפורשת של המאמן, עם הצהרה שהאחריות שלו.

## תרגיל שהמאמן כותב בעצמו

המאגר לא יכיל אף פעם את כל מה שמאמן טוב ממציא. לכן אפשר לכתוב תרגיל — שם, תיאור, סטים,
חזרות, משקל עבודה והערות — לנסות אותו באימון, ולסמן אם המתאמן ביצע אותו בסדר. עד הבדיקה הוא
נשמר כטיוטה ואינו נכנס לתכניות. משנסמן שהוא עבר, המערכת משבצת אותו בעצמה מכאן והלאה.

שלושה שדות נוספים — דפוס תנועה, שריר עיקרי וציוד — הם אופציונליים ומשפרים את השיבוץ
האוטומטי. בלעדיהם התרגיל נשמר ועובד, אבל ישובץ רק כתרגיל עזר.

## לולאת המשוב מהשטח

המאמן מעביר את האימון דרך המסך, וליד כל תרגיל יש כפתורים. כל לחיצה היא אירוע
שמשנה את הפרופיל, ולכן את התכנית הבאה:

| כפתור | מה קורה |
|---|---|
| רישום סט (משקל/חזרות/RPE) | נשמר בהיסטוריה, ומחושב יעד לשבוע הבא בפרוגרסיה כפולה |
| קל מדי | +5% עומס. ארבעה דיווחים כאלה מעלים את רמת המתאמן |
| קשה מדי | −10% עומס, ונספר לטובת המלצת שבוע הורדת עומס |
| **כאב בתרגיל** | התרגיל מוסר; המפרק שדווח הופך למגבלה פעילה בחומרה לפי עוצמת הכאב — וכל התרגילים הסותרים אותה נעלמים מהתכנית הבאה |
| טכניקה מתפרקת | הורדת עומס; בתרגיל מורכב — החלפה בגרסה פשוטה יותר |
| מכשיר תפוס | הציוד נחסם, והתכנית הבאה נבנית בלעדיו |
| החלפת תרגיל | החלפה מיידית לחלופה מדורגת, עם חישוב מרשם מחדש ובקרת איכות חוזרת |
| דילוג | שני דילוגים על אותו תרגיל מסירים אותו |
| תרגיל מוצלח | מקבל עדיפות בהמשך |
| **בדיקת תרגיל עבר / היה כאב** | מאשר את התרגיל למתאמן למרות המגבלה, או חוסם אותו לצמיתות עם הסיבה |

הצטברות סימני עומס יתר (קשה מדי / דילוגים / כאב / RPE גבוה) מפעילה המלצה
לשבוע הורדת עומס ומקדמת אליו את המחזור.

## מסד הנתונים

הנתונים של סטודיו הם התיק של הלקוחות שלו, ולכן שכבת האחסון בנויה סביב ההנחה שדברים משתבשים:

- **כתיבה אטומית** — כותבים לקובץ זמני ומחליפים רק כשהוא שלם. נפילה באמצע לא משאירה מסד פגום.
- **קובץ פגום נשמר בצד ולא נמחק**, והמערכת עולה נקייה במקום ליפול.
- **מיגרציית סכימה** — מסד ישן נטען ומתעדכן בשקט, בלי לאבד נתונים.
- **גיבוי אוטומטי** לפני כל פעולה הרסנית (ייבוא, איפוס, מחיקת סטודיו), עם שמירת עשרה גיבויים אחרונים.
- **בדיקת שלמות** שמאתרת הפניות שבורות — מתאמן שמשויך לסטודיו שנמחק, תכנית של מתאמן שאינו קיים.
- **ייצוא וייבוא** של המסד כולו לקובץ אחד, גם במצב דפדפן.
- **יומן שינויים** שמתעד כל פעולה ונגזם אוטומטית.

## שני מאמנים, אותם מתאמנים — פריסה משותפת בחינם

המערכת רצה בשתי צורות, ואותו קוד בדיוק מריץ את שתיהן:

| | איפה הנתונים | מי רואה אותם |
|---|---|---|
| **בדפדפן בלבד** (GitHub Pages, ארטיפקט, קובץ מקומי) | בדפדפן של מי שנכנס | רק הוא, רק במכשיר הזה |
| **שרת משותף** (Cloudflare Workers + D1, או `npm start`) | במסד אחד | כל מי שנכנס לחשבון הסטודיו, מכל מכשיר |

לסטודיו עם יותר ממאמן אחד צריך את השנייה. הפריסה חינמית, ויש לה שתי דרכים.

**מהדפדפן, בלי טרמינל** — הדרך הפשוטה יותר אם אין Node מותקן:

1. פותחים חשבון חינמי ב-[Cloudflare](https://dash.cloudflare.com/sign-up) (בלי כרטיס אשראי).
2. בלוח הבקרה: **My Profile → API Tokens → Create Token → Edit Cloudflare Workers**. מעתיקים
   את האסימון. את **Account ID** מעתיקים מכתובת לוח הבקרה (`dash.cloudflare.com/<המזהה>`).
3. בריפו ב-GitHub: **Settings → Secrets and variables → Actions → New repository secret**,
   ומוסיפים שניים: `CLOUDFLARE_API_TOKEN` ו-`CLOUDFLARE_ACCOUNT_ID`.
4. **Actions → "פריסה לשרת המשותף" → Run workflow.**

בסוף ההרצה מודפסת הכתובת. מאותו רגע כל עדכון שנדחף מתפרסם לבד.

**מהמחשב** — אם Node כבר מותקן:

```bash
git clone https://github.com/nitzantzadok/studio-training
cd studio-training
npm run deploy      # בונה, מריץ בדיקות, יוצר מסד D1 ופורס
```

בפעם הראשונה ייפתח דפדפן להתחברות ל-Cloudflare. בסוף מודפסת הכתובת —
`https://studio-training.<שם>.workers.dev` — וזו הכתובת שנותנים לכל המאמנים. כל אחד נכנס עם
שם המשתמש והסיסמה של הסטודיו ורואה את אותם מתאמנים.

**איך זה בנוי.** `src/server/api.js` הוא טבלת הנתיבים — הרשאות, מסד, מנוע — בלי שרת ובלי
מערכת קבצים. שני עוטפים דקים משתמשים בה: `src/server/server.js` (שרת Node) ו-`worker/index.js`
(פונקציה בקצה). כך אין שתי מערכות לתחזק, ואין התנהגות שקיימת רק באחת מהן.

**שלושה דברים שהפריסה המשותפת חייבת לעשות נכון**, ויש להם בדיקות:

1. **כתיבה מקבילה לא מוחקת עבודה.** שני מאמנים ששומרים באותו רגע הם המצב הרגיל, לא מקרה
   קצה. כל שמירה מותנית במספר הגרסה שנקרא; אם מישהו הקדים, הבקשה רצה שוב על המצב העדכני
   במקום לדרוס אותו.
2. **המסמך לא נתקע בתקרת גודל.** הוא נשמר בפרוסות, וארכיון התכניות מוגבל ל-12 האחרונות
   לכל מתאמן — רבעון של היסטוריה, בלי צמיחה בלי סוף.
3. **הסיסמאות עובדות בשני המקומות.** הגיבוב עבר ל-PBKDF2 דרך WebCrypto, שקיים גם ב-Node
   וגם בקצה. חשבונות ישנים שנוצרו ב-scrypt ממשיכים להיכנס — האלגוריתם נקרא מהרשומה עצמה.

המערכת היא כלי עזר למאמן מוסמך ואינה מחליפה אבחון או ייעוץ רפואי. במצבים רפואיים
