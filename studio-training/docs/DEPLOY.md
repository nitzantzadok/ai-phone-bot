# הפעלה בייצור — חשבונות אמיתיים לכמה סטודיואים

## שני מצבי הפעלה, וההבדל ביניהם

למערכת יש שני מצבים, והם לא זהים מבחינת אבטחה. חשוב לדעת מה שולחים ללקוח.

| | דף עצמאי (הקישור לשיווק) | שרת (ייצור) |
|---|---|---|
| התחברות | שם משתמש וסיסמה | שם משתמש וסיסמה |
| גיבוב סיסמה | PBKDF2 · 210,000 סיבובים (WebCrypto) | scrypt · N=16384 (בשרת) |
| היכן הנתונים | בדפדפן של המשתמש בלבד | במסד בשרת שלך |
| הפרדה בין סטודיואים | מפתח אחסון נפרד לכל חשבון | בעלות נאכפת בכל בקשה |
| גישה מכמה מכשירים | לא | כן |
| כמה מאמנים במקביל | מאמן אחד, מכשיר אחד | כל צוות הסטודיו |
| מתאים ל | הדגמה, ניסיון, מאמן עצמאי | סטודיו שמפעיל את זה באמת |

הדף העצמאי הוא הדגמה מלאה ועובדת — לא מוקאפ. אבל מי שמנקה את נתוני הדפדפן
מאבד את הנתונים, ואין גיבוי בענן. לכן הוא מיועד להתרשמות ולניסיון, ומעבר
לשימוש אמיתי נעשה מול שרת.

## הפעלת השרת

```bash
git clone <הריפו>
cd studio-training
npm run build          # בונה את מסך המאמן
node src/server/server.js
```

אין תלויות להתקין. Node 20 ומעלה.

### משתני סביבה

| משתנה | ברירת מחדל | למה |
|---|---|---|
| `PORT` | 4310 | פורט ההאזנה |
| `STUDIO_DB_FILE` | `data/db.json` | מיקום המסד. שים אותו על דיסק שנשמר בגיבוי. |
| `ANTHROPIC_API_KEY` | — | רק לזיהוי ציוד מתמונה. בלעדיו הצ'קליסט הידני עובד כרגיל. |

### מאחורי HTTPS — חובה

עוגיית המושב מסומנת `Secure` אוטומטית כשמגיעה הכותרת `X-Forwarded-Proto: https`.
בלי HTTPS העוגייה נשלחת בטקסט גלוי. הגדרת nginx מינימלית:

```nginx
server {
  listen 443 ssl;
  server_name studio.example.com;
  ssl_certificate     /etc/letsencrypt/live/studio.example.com/fullchain.pem;
  ssl_certificate_key /etc/letsencrypt/live/studio.example.com/privkey.pem;

  location / {
    proxy_pass http://127.0.0.1:4310;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;   # בלי זה העוגייה לא תסומן Secure
  }
}
```

### שירות שרץ תמיד

```ini
# /etc/systemd/system/studio-training.service
[Unit]
Description=Studio training programs
After=network.target

[Service]
WorkingDirectory=/srv/studio-training
Environment=PORT=4310
Environment=STUDIO_DB_FILE=/srv/studio-data/db.json
ExecStart=/usr/bin/node src/server/server.js
Restart=always
User=studio

[Install]
WantedBy=multi-user.target
```

## איך ההפרדה בין סטודיואים נאכפת

זה החלק שחשוב לא לשבור בשינויים עתידיים:

1. **לכל סטודיו יש `accountId`.** הוא נקבע ביצירה ולא ניתן לשינוי דרך ה-API —
   `putStudio` שומר את הבעלים הקיים גם אם גוף הבקשה לא כלל אותו.
2. **מתאמן שייך לחשבון דרך הסטודיו שלו.** אין למתאמן שיוך עצמאי שיכול לסטות.
3. **כל נתיב API סגור כברירת מחדל.** מי שאינו ברשימת `PUBLIC` דורש מושב תקף.
4. **אין פונקציית שליפה גלובלית בשימוש.** `listStudiosFor(accountId)` ו-
   `listTraineesFor(accountId)` הן הדרך היחידה; נתיב חדש שישכח לסנן פשוט לא יקבל נתונים.
5. **גוף הבקשה אינו מקור סמכות.** שליחת `trainee` שלם בגוף הבקשה לא עוקפת בעלות —
   הנתונים תמיד נקראים מהמסד ומאומתים.
6. **משאב של חשבון אחר מחזיר 404 ולא 403.** "אין הרשאה" היה מאשר לזר שהמזהה קיים.

הבדיקות ב-`tests/auth.test.js` מנסות לשבור בדיוק את זה — כולל זיוף מזהים,
עוגייה מזויפת, וניסיון למחוק מתאמן של חשבון אחר. הן חייבות להישאר ירוקות.

## גיבוי

```bash
# גיבוי יומי של המסד
0 3 * * * cp /srv/studio-data/db.json /backup/db-$(date +\%F).json
```

המערכת שומרת גם 10 גיבויים אוטומטיים אחרונים לצד המסד לפני כל פעולה הרסנית
(מחיקה, ייבוא, איפוס). כל סטודיו יכול לייצא את הנתונים שלו מהמסך —
הייצוא מכיל רק את החשבון שלו, ולעולם לא גיבובי סיסמאות או מושבים פעילים.

## שחזור סיסמה

אין כרגע מסלול "שכחתי סיסמה" — אין שליחת דואר במערכת. מנהל המערכת יכול
לאפס סיסמה ידנית: למחוק את שדות `salt`/`hash` של החשבון במסד ולתת למשתמש
לפתוח חשבון מחדש, או להריץ `hashPassword` מ-`src/store/auth.js` ולהחליף אותם.
אם תוסיף שליחת דואר, זה המקום להוסיף גם טוקן איפוס עם תוקף קצר.
